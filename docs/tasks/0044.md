범위: 좁은 contextBridge, sandbox, contextIsolation, 신뢰된 앱 프레임 검증, 외부 OAuth 창 분리. 사용자 검증: 로그인(일반/Google), 창 조작, 할 일·설정·동기화·업데이트 안내. 자동 테스트 후 이 지점에서 멈춘다. 서버·DB 동작은 유지한다.

완료 조건: Node/remote/env 노출 제거, sender·채널 경계 테스트 및 사용자 앱 회귀 확인.

## 구현된 내용

- 독립된 sandbox preload의 고정 request 목록과 이벤트 구독만 contextBridge로 공개. Electron 객체/IPC 원본 event/전체 env/remote 접근 제거.
- 모든 앱 창에 contextIsolation·sandbox 강제, 모달 입력은 크기 등 허용된 속성만 사용.
- main frame과 정확한 앱 문서 URL, 창 역할을 IPC에서 확인. 창 ID·구독 대상 ID는 event.sender로 결정.
- 인증·작업 데이터는 메인 창만 요청/구독 가능. updater는 진행 이벤트와 계속 버튼만 허용.
- 외부 탐색·webview·임의 새 창 차단. 설정된 Google 로그인 시작 URL만 비권한 OAuth 창으로 열고 postMessage 유지.
- 앱 문서에 CSP 적용. production 스크립트는 self만 허용, 개발 HMR 연결은 별도 허용.
- 메인 창 이전의 updater 구독 경로를 추가하고 진행 이벤트의 null request ID 형식을 renderer 계약과 일치시킴.

## 검증 및 남은 범위

- Desktop Jest: 11 suites, 52 tests 통과.
- windowSecurity.test.cjs: 6개 테스트 통과. 채널 제한, 원본 event 차단, URL/프레임/역할, 모달 옵션, OAuth/CSP, 기존 구독 목록을 검증.
- 실제 Electron synthetic 통합 테스트 통과: Node/env 접근 불가, 타 창 ID 구독 위조 방지, 권한 없는 updater 요청 거부, 진행 알림, CSP inline script 차단, OAuth 창 bridge 부재와 postMessage 확인.
- production renderer 빌드 성공(기존 ESLint 경고 있음). 설치 파일은 만들지 않았고 제품 버전은 올리지 않았다.
- 실제 Google 계정 인증, Windows 창 동작, 사용자 기존 DB의 편집·동기화는 자동 검증하지 않았다. 사용자 검증이 끝날 때까지 WIP.
- Electron 지원 버전·OS 키 저장소는 #45, 로그 전체 감사는 #56에서 진행. 이번 변경을 E2EE 활성화로 표시하지 않는다.

## 사용자 검증 — 여기서 중단

루트에서 기존 dev 프로세스를 종료하고 `pnpm run dev:desktop`으로 다시 실행한다. preload/main 변경은 renderer 새로고침만으로 반영되지 않는다. 테스트 계정과 테스트 항목을 사용하고 개인정보/토큰을 로그로 보내지 않는다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 일반 로그인 및 Google 로그인 | 팝업 인증 후 정상적으로 홈에 진입 |
| 최소화·최대화·복원·닫기·트레이 다시 열기 | 기존 창 동작 유지 |
| 할 일/메모/하위 항목/카테고리 편집 후 재실행 | 항목이 보존되고 설정의 동기화 상태 갱신 |
| 설정·달력·메뉴 열기 | 빈 화면이나 IPC 예외 없이 조작 가능 |

개발 모드에서는 시작 업데이트 창이 생략된다. updater는 synthetic 통합 테스트로 먼저 확인했으며 실제 서명 설치본의 시작/업데이트 회귀는 #45/#46/#57에서 확인한다.

실패 시 수행한 동작과 오류 코드만 보고한다. 정상 확인 전에는 후속 사용자 데이터·키 작업을 진행하지 않는다.

근거: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [sandboxed preload](https://www.electronjs.org/docs/latest/tutorial/sandbox).
