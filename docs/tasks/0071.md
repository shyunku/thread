## 결함과 수정

| # | 위치 | 결함 | 수정 |
| --- | --- | --- | --- |
| 1 | `POST /v1/google_auth/signup` (인증 없음) | 본문의 `auth_id`로 기존 계정을 찾아 비밀번호 확인 없이 본문의 `google_auth_id`를 기록. Google ID도 클라이언트 값을 그대로 신뢰. 남의 아이디만 알면 자기 Google을 연결해 그 계정 토큰을 받을 수 있었다 | 콜백이 Google 확인 후 10분짜리 연결 토큰(`linkToken`, 접근 토큰과 분리된 파생 키로 서명)을 발급하고, signup은 이 토큰의 신원만 사용. 기존 계정 연결은 저장된 비밀번호 해시와 상수 시간 비교 후에만 허용(불일치 401). 이미 연결된 Google·계정은 409 |
| 2 | `GET /v1/google_auth/login_callback` | 로그인 토큰이 든 결과를 `window.opener.postMessage(..., '*')`로 전송. 임의 사이트가 로그인 팝업을 열면 토큰을 받을 수 있었다 | 결과를 실행되지 않는 JSON(`<script type="application/json">`)으로만 두고 `postMessage` 제거. CSP `default-src 'none'`, `X-Frame-Options: DENY`, `no-store`. 데스크톱 메인 프로세스가 정확한 콜백 주소에서만 읽어 opener 창에 IPC로 전달하고 창을 닫음 |
| 3 | `POST /v1/google_auth/signup_mobile` | Google ID 토큰 서명만 확인하고 `aud`·`iss`·`email_verified`를 확인하지 않음. 다른 앱용 토큰으로 로그인 가능 | `iss`, `aud`(허용 목록), 만료, `email_verified` 확인. 누락 claim의 타입 단언 패닉 제거 |
| 4 | `AuthMiddleware` Google access token 대체 경로 | tokeninfo의 `audience`를 확인하지 않음 | 허용 목록에 없는 audience 거부 |

허용 audience는 서버의 `GOOGLE_OAUTH2_CLIENT_ID`와 선택 환경 변수 `GOOGLE_OAUTH2_ALLOWED_AUDIENCES`(쉼표 구분)다. 모바일이 다른 클라이언트 ID를 쓰면 여기에 추가해야 한다.
