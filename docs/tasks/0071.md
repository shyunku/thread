선행: 없음 · 완료 조건: `POST /v1/google_auth/signup`이 클라이언트가 보낸 Google 식별자를 그대로 믿지 않고, 기존 계정에 Google을 연결할 때 해당 계정의 인증을 요구한다. 운영 DB에서 비정상 연결 흔적 여부를 확인한다.

#70 사전 확인(2026-10-02) 중 발견했다. 운영 서버에 대한 시험 요청은 하지 않았다.

## 문제

| 항목 | 내용 |
| --- | --- |
| 위치 | `services/api/controllers/v1/google_auth.go` `SignupWithGoogleAuth`, 라우트 `POST /v1/google_auth/signup` (인증 미들웨어 없음) |
| 결함 1: 계정 연결 | 요청 본문의 `auth_id`로 기존 계정을 찾고, 그 계정에 Google 연결이 없으면 `encrypted_password` 확인 없이 본문의 `google_auth_id`·`google_email`을 기록한다 |
| 결함 2: Google 식별자 미검증 | `google_auth_id`는 클라이언트가 보낸 값이며 서버가 Google 토큰으로 확인하지 않는다. 임의의 Google ID로 새 계정을 만들어 선점할 수도 있다 |
| 결과 | 다른 사람의 `auth_id`를 아는 공격자가 자기 Google ID를 그 계정에 연결한 뒤 Google 로그인(`/v1/google_auth/login` 콜백 또는 Google access token을 받는 `AuthMiddleware` 대체 경로)으로 그 계정의 Thread 토큰을 받을 수 있다 |
| 영향 범위 (추정) | 계정 접근·계정 메타데이터 조회. v3 데이터는 기기 키로 암호화·서명되므로 내용 복호화나 서명된 쓰기는 별도 기기 키 없이 불가능하다고 보지만, 계정 토큰으로 가능한 API 전체에 대한 영향 검토가 필요하다 |
| 응답 노출 | 응답 `UserEntity`에서 비밀번호 해시는 `json:"-"`로 제외되어 있다 |
