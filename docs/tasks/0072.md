# Task 72: 리프레시 토큰 회전·세션 폐기

생성: 2026-10-02 17:42 · 갱신: 2026-10-03 16:04 (KST) · 상태: 🟣 VFY
선행: #71 · 완료 조건: 리프레시 시 이전 리프레시 토큰을 폐기하고, 로그아웃과 계정 전체 세션 폐기를 제공한다. 비밀번호 변경·Google 연결 변경 시 다른 세션을 끊을 수 있다. 재사용된 리프레시 토큰을 탐지하면 해당 계정의 세션을 모두 폐기한다.

#71 영향 검토(2026-10-02)의 추가 발견 B다.

## 이전 상태

| 항목 | 내용 |
| --- | --- |
| 리프레시 | `POST /v1/auth/refreshToken`이 새 access·refresh 토큰을 발급하지만 이전 refresh 토큰을 지우지 않았다. 서버는 refresh 토큰 서명을 확인하지 않고 헤더 값을 Redis 키로 그대로 조회했다 |
| 폐기 | `deleteRefreshToken`은 정의만 있고 호출되지 않았다. 로그아웃·세션 폐기 API가 없었다 |
| 결과 | 토큰이 한 번 유출되면 갱신을 반복해 무기한 유지되고, 끊을 방법이 없었다 |
| 데스크톱 로그아웃 | 로컬 인증 정보만 지우고 서버에는 알리지 않았다 |

## 결정 (사용자, 2026-10-03)

| 항목 | 결정 |
| --- | --- |
| 기존 세션 | 자연 전환. 배포 전 refresh 토큰은 다음 갱신 때 한 번만 새 세션으로 바뀐다. 세션 ID가 없는 기존 access 토큰은 만료(최대 3시간)까지 허용한다. 재로그인 없음 |
| access 토큰 | 즉시 차단. access 토큰에 세션 ID(`sid`)를 넣고 인증이 필요한 모든 요청에서 Redis로 세션을 확인한다 |
| Google 연결 | 연결 시 다른 세션을 끊지 않는다. 필요하면 "다른 곳에서 모두 로그아웃"을 쓴다. 비밀번호 변경 API는 아직 없어 해당 없음 |

## 설계

| 항목 | 내용 |
| --- | --- |
| 세션 | 로그인마다 `sid`를 만든다. Redis `thread:session:` 아래에 현재 토큰(`rt:<해시>`), 회전된 토큰(`used:<해시>`, 원래 만료까지 보관), 활성 세션(`sid:<sid>`), 계정별 세션 목록(`user:<uid>`), 기존 방식 차단 표시(`legacy-off:<uid>`)를 둔다. 토큰 원문은 저장하지 않는다(SHA-256) |
| 회전 | refresh 토큰 서명·만료를 먼저 확인한 뒤 Lua 스크립트로 원자적으로 교체한다. 만료는 기존처럼 갱신 시점부터 다시 7일이다 |
| 재사용 탐지 | 회전된 토큰이 다시 오면 그 세션을 끊는다(`REFRESH_TOKEN_REUSED`). 응답 유실에 대비해 30초 안이고 후속 토큰이 아직 쓰이지 않았으면 후속 토큰을 새것으로 바꿔 준다 |
| 기존 토큰 전환 | 서명이 맞는 기존 refresh 토큰만 Redis 원래 키에서 한 번 꺼내 새 세션으로 바꾼다. 세션 키 등 다른 키는 건드리지 않는다 |
| API | `POST /v1/auth/logout`(refresh 토큰 헤더, 항상 204), `POST /v1/auth/sessions/revoke`(access 토큰, `{"keep_current": true}`면 현재 세션 유지). 모두 끊기는 기존 방식 토큰과 Google access 토큰 경로도 막는다 |
| 접근 확인 | v1 `AuthMiddleware`와 v3 `UserPrincipal`이 세션을 확인한다. 끊긴 세션은 401, Redis 장애나 미설정은 503(통과시키지 않음) |
| 데스크톱 | 로그아웃 시 서버 세션을 먼저 끊고(실패해도 로컬 로그아웃 진행) 토큰을 지운다. 계정 탭 "다른 곳에서 모두 로그아웃" 활성화. 만료되었거나 세션 ID가 없는 토큰이면 한 번 갱신 후 재시도 |
