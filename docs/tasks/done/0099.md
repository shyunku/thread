## 기록

- 2026-10-06 05:00: 결정. 위치는 `docs/patchNotes/` 아래 플랫폼별 폴더, 형식은 JSON. 출시 확정 뒤 빌드 전에 작성한다. 업데이트 후 처음 열 때 창을 띄우고(PC·모바일 모두), "다시 보지 않기"와 설정의 창 보기 토글은 같은 설정이다. 설정에서 업데이트 내역을 볼 수 있다. 과거 버전(PC 2.0.9 이하, 모바일 2.0.0)은 채우지 않고 다음 버전부터 쓴다.
- 2026-10-06 05:26: 시안 2차(사용자 피드백). PC 설정은 "업데이트 내역" 카드 하나, 누르면 최근 12개(창으로/카드 안 펼치기 비교). 문구는 사용자가 체감하는 변화만 한 문장 제목으로, 세부는 선택·문장마다 한 줄. 밀린 업데이트 5개 이상이면 버전+요약 카드로 접어 표시. 아이콘 48px, 제목 "업데이트를 완료했어요", 세부 글자 12px·muted. 창 관련 변경은 모바일에도 적용.
- 2026-10-06 06:04: 시안 3차. 버전 요약은 명사로 끝냄(예: "캘린더 UI 개선"). 아이콘은 실제 아이콘(PC react-icons Io5, 모바일 lucide)으로 구현. 모바일 "업데이트 후 변경 내용 보기"는 설정 > 일반으로 옮기고 업데이트 내역 화면은 목록만.
- 2026-10-06 06:11: 시안 확정("이대로"). PC·모바일 모두 "업데이트 후 변경 내용 보기"는 설정 > 일반, PC 업데이트 내역은 창으로 열기, 최대 12개·5개 이상이면 접기, 종류 순서는 새 기능 → 개선 → 수정. 구현은 다음 작업.
- 2026-10-06 14:47: 구현. `scripts/patchNotes.cjs`가 `docs/patchNotes`를 엄격히 검사해 앱마다 `src/generated/patchNotes.json`(플랫폼별 최신 12개, 종류 순서 새 기능 → 개선 → 수정)을 만든다. `--check`는 테스트에서 생성 파일이 최신인지, `--require desktop:win`은 `pnpm build:desktop`에서 현재 버전 내역이 있는지 확인한다. 마지막으로 본 버전: PC는 userData의 `patch-notes.json`(`datafiles`나 `e2ee`가 있으면 기존 설치로 보고 현재 버전만 보여 줌, 새 설치는 바로 기록), 모바일은 prefs의 `patchNotesSeen`(시작할 때 로그인된 계정이 없으면 새 설치로 기록). "다시 보지 않기"는 `showPatchNotes`(PC 앱 설정, 모바일 prefs)를 끈다. 5개 이상이면 접힌 카드, 설정에서 연 내역은 항상 카드. 검증: 데스크톱 jest 174개·node 263개, 모바일 jest 37개, tsc 통과. 합성 내역으로 PC 렌더러 미리보기(업데이트 후 2개·6개·펼침, 내역 창, 설정 일반·정보)와 Android 에뮬레이터(SECURE_LOGS Metro, 다크 2개·라이트 7개·펼침, 내역 화면, 설정)를 캡처해 시안과 비교했다. iOS·Mac 실행 확인과 실제 업데이트 확인은 남음.
- 2026-10-06 15:37: 결정 변경(사용자). 정식 버전은 모든 플랫폼 내역을 쓰고, 베타 테스트판도 내역을 쓴다. 정식 빌드는 베타 내역을 보여 주지 않으므로 정식 내역에 베타 변경을 모두 담는다. 앱은 자기보다 높은 버전 내역을 보여 주지 않으므로 다음 출시 내역을 미리 써 둘 수 있다. 초안: PC Windows 2.1.0, 모바일 2.0.0(Android·iOS, 첫 정식), 모바일 2.0.0-beta.2(Android·iOS). Mac은 출시가 정해지지 않아 쓰지 않았다. 다중 에이전트 검토로 사실과 다른 항목(PC 속도 개선은 PC 확인 전이라 뺌, 한 번에 업데이트는 다음 업데이트부터 적용, 캘린더 변경 범위), 플랫폼 차이(iOS Google 로그인 없음, 잠금 방식), 같은 변경의 문구 통일을 고쳤다. 같은 검토에서 모바일 `patchNotesSeen` 검사식이 깨져 마지막으로 본 버전이 저장되지 않던 버그(b177530)를 찾아 고쳤다.
