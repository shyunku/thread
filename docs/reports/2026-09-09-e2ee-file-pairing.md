# File-based device pairing

기록: 2026-09-09 23:07 (KST).

개발 설정 → 보관함 잠금 해제 → 파일로 기기 연결을 추가했다.

1. 기존 owner 기기는 복구 확인과 서버 등록을 먼저 수행한다. 화면에 보관함 지문을 표시한다.
2. 새 데스크톱은 같은 계정/서버에서 기존 기기의 지문을 입력한다. 서버 genesis를 해당 지문으로 검증하고 별도 기기 키·10분 만료 요청을 암호화 저장한다. 새 데스크톱 권한은 조회/편집이며 다른 기기 승인 권한은 없다.
3. .thread-pair-request 파일을 기존 기기로 전달한다. 기존 기기는 요청 지문/권한/만료를 보고 새 기기의 지문과 비교한 뒤 OS 또는 보관함 비밀번호로 재인증한다.
4. 서버 승인·전체 서명 이력 재확인 후에만 .thread-key-transfer를 저장한다. 저장을 취소해도 서버 승인은 되돌리지 않으며 같은 요청으로 재인증·저장을 재시도할 수 있다.
5. 새 기기는 파일을 열고 수신자·요청·서명·키 세대·서버 승인·현재 권한을 대조한다. 기존 owner 키를 덮어쓰지 않고 별도 paired-device 영역에 보존한다.

파일은 native dialog로 선택하고 신규 저장 시 exclusive 생성/fsync한다. 입력 파일 크기는 요청 2 KiB, 전달 512 KiB로 제한한다. 잠금/계정 변경은 요청과 늦은 파일 작업을 중단한다. 연결 과정에서 확인한 membership checkpoint도 보존해 알려진 이력보다 과거로 돌아가는 응답을 거부한다.

검증: 관련 Node 17개, React UI 6개, 신규 화면 lint 및 renderer production build 통과(기존 경고). 독립된 두 encrypted SQLite의 왕복·동일 요청 재시도·수신기 재열기·잘못된 pin·만료·미승인 전달·서버 이력 rollback·재인증 취소를 synthetic transport로 확인했다. UI는 지문 확인 선행, 비밀번호 입력 제거, unmount 후 늦은 응답 차단을 확인했다.

실제 서버/두 기기/사용자 키로 실행하지 않았다. QR 문자열 codec은 기존 구현이지만 QR 이미지·카메라 및 모바일 앱 연결은 아직 미연결이다. 받은 identity를 일반 E2EE sync에 선택하는 bootstrap과 epoch 연결도 남아 있다. 키 연결 완료는 기존 데이터 이관/동기화 완료가 아니며 운영 이관은 #57에서 별도 승인한다.
