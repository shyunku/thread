# SQL backup migration rehearsal

검증 일시: 2026-09-07 01:23 (KST)

## 범위와 격리

사용자가 제공한 .tmp/thread.sql.gz 사본만 사용했다. 운영 DB·실제 env·사용자 SQLite·운영 로그에는 접근하지 않았다. 개인정보/계정 ID/데이터 원문은 출력하거나 문서에 기록하지 않았다.

MySQL 8 임시 컨테이너는 network=none, 공개 포트 없음, 호스트 bind/named volume 없음, /var/lib/mysql은 tmpfs로 구성했다. 복원 기준 사본과 이관 사본을 별도 DB에 두었다. 백업과 임시 바이너리는 Git 제외 대상인 .tmp에 유지한다.

## 결과

- gzip 무결성 검사와 SQL 복원 성공. 제공된 압축 파일과 컨테이너 복사본 SHA-256 일치.
- schema5 준비 및 재실행 성공. schema 준비 후 기존 테이블의 정렬된 데이터 dump가 기준 사본과 SHA-256 일치.
- 전체 사전 점검 성공. 계정 1개 이관 성공 및 verify-all 통과.
- task 3개, category/subtask/관계 0개, 이관 기록 1개. 이관 코드의 저장 필드/건수 대조를 통과했다.
- 이관 후 기존 모든 테이블 데이터 dump가 기준 사본과 SHA-256 일치.
- apply-all 재실행은 migrated=0. 재실행/verify 전후 전체 테이블 데이터 dump가 SHA-256 일치하여 epoch/이관 기록/행의 무변경을 확인했다.

비교는 내용 출력 없이 컨테이너 안에서 수행했다. 최소 MySQL 이미지에 cmp가 없어 비교 도구 호출이 한 차례 중단되었으며, 데이터 이관 전에 SHA-256 비교로 변경한 뒤 전체 절차를 통과했다.

## 한계와 다음 단계

이 백업에 포함된 데이터의 서버 이관만 검증했다. category/subtask/관계가 있는 실제 사본, 사용자 SQLite pending, 화면/Google 로그인/다기기/모바일 및 부하 테스트를 검증한 것으로 간주하지 않는다. 기존 synthetic 검증과 별개로 실제 기기 검증은 남아 있다.

운영 배포는 하지 않았다. 검증 후 임시 컨테이너와 내부 사본을 제거했으며 제공된 압축 백업은 보존했다. 운영 전에는 모든 writer를 중단하고 최신 백업을 다시 확보해야 한다. v2 쓰기 이후 구 DB를 덮어쓰는 단순 rollback은 금지한다.
